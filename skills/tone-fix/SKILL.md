# tone-fix — 말투 지적 반영

지적받은 표현을 ① 지금 산출물에서 고치고 ② 규칙 파일에 넣고 ③ 기계로 잡히면 사전에 넣은 뒤 ④ 검사 스크립트 자체 테스트까지 돌리는 절차.
인자로 지적 내용이 오면 그걸, 없으면 직전 사용자 메시지에서 지적한 문장을 대상으로 삼을 것.
아래 경로는 전부 이 스킬 폴더 기준. 실제 위치는 `readlink -f` 로 확인.

## 파일

| 파일 | 역할 |
|---|---|
| `rules.md` | 문체 규칙 정본. `install.py` 가 각 에이전트의 전역 규칙 자리에 연결. 200줄 아래 유지 |
| `dict.txt` | 금지어 사전. `정규식<TAB>대체 제안`, `#` 줄은 주석. 세 hook 이 같이 읽음 |
| `hooks/response-lint.py` | 응답 직후(Stop · SubagentStop) 사전 1회 매칭 또는 빈도 지표 누적이면 다시 쓰라고 요구. 백틱 · 따옴표 안은 제외 |
| `hooks/commit-pr-lint.py` | `git commit` · `gh pr create/edit/comment` 직전 금지어 · 트레일러 · 줄 끝 "~한다" 종결을 막음 |
| `hooks/comment-lint.py` | 파일 저장 직전 코드 주석 · 테스트 이름의 금지어 · "~한다" 종결, 마크다운 금지어를 막음 |
| `install.py` | 설치된 에이전트에 연결. 여러 번 돌려도 같은 결과. `--check` 는 미리 보기 |

## 먼저 확인: 원본 머신인가

`test -f .tone-fix-source` 로 확인.

- **있으면(원본 머신)** 아래 절차대로 고칠 것.
- **없으면(설치본)** 이 폴더를 고치지 말 것. `npx skills update` 가 폴더를 통째로 갈아 끼워 수정이 사라짐. 지금 산출물만 고치고(절차 1), 규칙 파일 · 사전에 넣을 줄을 사용자에게 보여 주고 끝낼 것. 사용자가 원본 머신에서 반영함.

## 절차

1. **지금 산출물부터 고칠 것.** 지적받은 문장이 커밋 · 주석 · 문서 · 응답 어디에 있든 먼저 고쳐 쓰고, 같은 산출물 안의 같은 패턴도 `grep` 으로 찾아 같이 고칠 것.
2. **`rules.md` 에 한 줄 추가.** 맞는 절을 골라 "나쁨 → 좋음" 한 쌍으로.
   - 단어 하나 → "금지어" 절에 `단어 → 대체어`
   - 문장 습관 → "AI 티 나는 문장 습관" 의 해당 번호 끝에 예시 한 쌍. 맞는 번호가 없을 때만 새 번호
   - 주석 · 커밋 · PR · 보고 문서 한정 → 그 절에
   - 사건 경위 · 날짜 · 서사는 쓰지 말 것. 이미 같은 규칙이 있으면 예시만 보강
   - 회사 · 특정 프로젝트에만 해당하는 규칙은 `rules.md` 가 아니라 그 머신의 보충 규칙 파일에(예: `~/.claude/rules/*-local.md`)
3. **사전에 넣을지 판단.** 정규식 한 줄로 오탐 없이 잡히는 단어 · 어구면 `dict.txt` 에 추가. 다른 뜻으로도 흔히 쓰는 말(`원장님` 처럼)은 부정 전방탐색(`(?!님)`)을 붙이거나 넣지 말 것. 문장 구조 문제는 사전 대상 아님.
4. **검증.**
   ```bash
   for h in response-lint commit-pr-lint comment-lint; do python3 hooks/$h.py --self-test; done
   wc -l rules.md
   # 사전에 넣었으면: 나쁜 예는 걸리고 좋은 예는 안 걸리는지
   python3 - <<'EOF'
   import re
   rules=[l.rstrip("\n").split("\t") for l in open("dict.txt",encoding="utf-8") if l.strip() and not l.startswith("#")]
   for s in ["<나쁜 예>", "<좋은 예>"]:
       print(s, "->", [p for p,_ in rules if re.search(p, s)])
   EOF
   python3 install.py   # 규칙 본문을 복사해 넣는 에이전트가 있으면 새 본문으로 갱신
   ```
5. **보고.** 고친 산출물 문장(전 → 후), `rules.md` 에 넣은 줄, 사전 추가 여부, 검증 결과만 짧게.

## 지킬 것

- 새 규칙은 에이전트 메모리(자동 메모리 폴더 등)에 쓰지 말 것. 메모리는 프로젝트마다 따로라 다른 곳에서 안 보임.
- `rules.md` 문장은 "~할 것" · 명사형으로 끝낼 것. 매 세션 읽히는 글이 "~한다" 로 끝나면 그 말투를 따라 쓰게 됨.
- `rules.md` 의 지시어("해라체" 같은 말)를 산출물에 옮기지 말 것.
- 에이전트 설정 파일이나 hook 코드를 바꿀 땐 먼저 사용자에게 확인받을 것. `install.py` 는 바꾸기 전에 `~/.local/state/tone-fix/backups/` 에 백업함.
- `# ai-tell-ok` 우회는 사용자가 오탐이라고 허락했을 때만.

## 함정

- 응답에서 금지어를 설명할 땐 백틱으로 감쌀 것. 그냥 쓰면 응답 검사가 전체 재작성을 요구함.
- 마크다운을 heredoc 으로 쓸 땐 `<<'EOF'`. 따옴표 없는 `<<EOF` 안의 백틱은 명령 치환돼서 사라짐.
- 셸이 zsh 면 bash 연관 배열이 안 됨. 여러 파일 처리는 python 으로.
- Claude Code 에서 규칙 로드 확인은 `/context` 의 Memory files 목록. `/memory` 에는 `rules/` 파일이 안 나옴.
- "~한다" 검사는 줄 끝만 봄. 문장 중간 종결이나 "여기다" 같은 줄임꼴은 못 잡음.
- 셸 명령(`sed` · heredoc)으로 쓴 파일은 주석 검사를 안 거침.
