# 회귀 하네스 — 렌즈를 고칠 때마다 돌려라

렌즈(각 SKILL.md의 게이트/목록)는 프롬프트다. 프롬프트를 고치면 **오탐이 늘거나 커버리지가 줄 수 있다.** 이 폴더가 그걸 즉시 잡는 A/B 테스트다.

## 구성
- `fixtures/` — 도메인 3종 × 수준(상/중/하) TS 파일. 상 수준엔 "지적하면 안 되는 함정"이 심겨 있음.
- `ANSWER-KEY.md` — 각 픽스처에 뭘 심었는지(진짜 결함 / 함정 / 누락). **에이전트에게 절대 노출 금지.**

## 채점 축
- **Recall**: 하/중 픽스처의 심은 결함을 잡나
- **오탐(FP)**: 상 픽스처의 "괜찮은 것"을 지적하나 ← 기계적 적용 지표
- **문서역행**: 원문이 금지한 지적("인터페이스 뽑아라" 등)을 하나 ← 핵심
- **Calibration**: overallLevel이 하<중<상으로 맞나

## 재검증 절차 (렌즈 수정 후)
1. 해당 도메인 픽스처들을 리뷰어 서브에이전트에 준다. **맥락 0, 렌즈 파일만 Read시킴.**
2. 파일당 2~3명(FP는 희귀 이벤트라 표본 필요). 스키마: `{ overallLevel, primary[], other[] }`.
3. 회수 후 ANSWER-KEY와 대조. 상 픽스처 primary가 비고 하/중 결함을 잡으면 통과.

## 실측 baseline (이 렌즈들이 통과한 값)
- comment-good/solid-good/solid-good2/test-good: **primary 오탐 0**
- comment-medium: 0/2(맨몸) → **3/3**(렌즈)
- solid-medium: 0/2 → **2/2** (v1.1)
- 하드 함정("쪼개라/전략패턴/인터페이스"): **6명 전원 0**

## 알려진 교훈
- 렌즈의 "지적 금지" 목록이 고민감 상태에서도 함정을 막는 핵심. 신호를 추가할 땐 반드시 상 픽스처로 FP 회귀 확인.
- "값 객체 후보" 같은 광범위 신호는 good 코드에 노이즈를 유발 → "같은 검증 2곳 이상 반복"으로 하드 게이트할 것(v1→v1.1에서 이 이유로 수정).
