# 렌즈 — 대상별 조사 체크 항목

주제에 해당하는 절을 골라 조사원 질문에 섞어 넣습니다. 한 조사에 여러 렌즈가 들어갈 수 있고, 새 종류의 대상이 나오면 절을 하나 추가합니다. 각 절의 "표 칸"은 brief 의 후보 표에 더하는 칸입니다.

## AI 모델 (호스팅 모델 · 오픈 가중치)

세 층을 순서대로 팝니다. 아래 층은 위 층이 확인돼야 성립합니다.

**1층 표면**
- 모델 페이지 · GitHub · 모델 카드: 입력 스키마, 출력 해상도, 지연, 공개일, 최신 버전 날짜, 버전 수, 실행 수.
- 단가: 공식 가격표 원문. Replicate 는 페이지 HTML 의 `billingConfig` JSON(로그인 불필요), 입력 스키마는 `/<owner>/<model>/api/schema`.
- 공식 문서의 지원 조건 · 권장 입력 · "피할 것(Avoid · Limitations)" 절을 원문 인용으로. 이게 평가 세트의 "기준 · 중간 · 어려움" 난이도 근거가 됩니다.
- 라이선스: 코드 · 가중치 · 호스팅 약관(실제 인물 사진 등 민감 입력 허용 여부, 출력 소유, 고객 데이터 학습 사용).

**2층 계보**
- 모델 카드 · README 가 인용하는 논문, 기반 모델(FLUX · SD · DiT 계열 등), 학습 데이터셋과 각각의 라이선스.
- 기반 모델이 비상업이면 파생 모델도 "성립해도 못 씀" 후보. 계보를 못 찾으면 `[미확인]` 으로 남기고 3층으로 내려가지 않습니다.

**3층 논문 유추**
- 인용 논문과 같은 과제의 벤치마크 논문에서 limitation · failure case · 실험 조건을 뽑습니다: 어떤 입력에서 성공률이 높았고 어떤 조건(각도 · 가림 · 무늬 · 글자 · 소재 · 해상도 · 개수)에서 깨졌는지.
- 표기는 반드시 `[논문→유추]`. 이 모델에서 재현되는지는 미확인이므로 결론이 아니라 **평가 세트 후보 · 실패 태그 후보**로만 씁니다.
- 실례: 가상 착용 모델 조사의 평가 설계에서 실패 태그 17개 중 7개, 평가 세트 난이도 "어려움" 절반이 VTBench · DAT · OmniTry 논문에서 왔습니다.

**표 칸 추가**: 기반 모델 · 인용 논문 / 가중치 · 학습 데이터 라이선스 / 문서가 밝힌 Avoid 조건 / 논문 유추 한계

## 라이브러리 · 프레임워크

- 공식 문서는 context7(`resolve-library-id` → `query-docs`)로 먼저. 블로그 예제보다 문서 원문.
- 실행 환경: Node · Python · WASM · ONNX 중 무엇으로 돌아가는지, 우리 서버 스택(brief 의 운영 환경)에서 공식 지원인지. 미해결 이슈 번호가 있으면 적습니다.
- 라이선스(코드 + 동봉 모델 · 데이터), 마지막 커밋 · 릴리스 날짜, 별 수, 유지보수 상태.
- 의존성 무게(설치 크기 · 네이티브 빌드 필요 여부), 알려진 플랫폼 문제(WSL · Apple Silicon 등).
- 대체 후보와의 차이를 같은 작업 기준으로.

**표 칸 추가**: 실행 환경 / 마지막 릴리스 / 네이티브 의존

## 벤더 API · SaaS

- 공식 가격표 원문(단위: 호출 · 크레딧 · 토큰), 무료 구간, 최소 결제.
- 약관: 데이터 보관 기간, 고객 데이터 학습 사용 여부, 출력 소유권, 금지 용도, 지역 제한.
- 계정 · 키 필요 여부(brief 의 "있는 계정"과 대조. 없으면 "사용자 결정 필요").
- 상태: 공개일, GA · Preview · Deprecated, 종료 예정일, 상태 페이지 · 변경 이력.
- 한국 사용자 · 한국어 입력 적용 사례.

**표 칸 추가**: 계정 유무 / 데이터 보관 · 학습 사용 / 상태(GA · Preview · 종료 예정)

## 방법론 · 이론 (정답이 애매한 과제)

- 학술 근거와 업계 관행을 분리해 적습니다. 어느 것이 논문이고 어느 것이 실무 통념인지.
- 측정 가능성: 그 개념을 수치로 바꿀 수 있나, 어떤 측정량에 대응하나, 측정 신뢰도 연구.
- 사람 간 일치도: 전문가끼리도 갈리는지, 수치(kappa 등)가 있는지. 없으면 "없음" 자체가 결론.
- 공개 데이터셋 · 오픈소스 구현: 크기, 라벨을 누가 붙였나, 라이선스, 보고된 정확도.
- 국내 자료(KCI · RISS · 학회지)와 해외 자료를 따로.

**표 칸 추가**: 근거 종류(논문 · 관행) / 측정량 / 사람 간 일치도

## 평가 · 실측 설계

- 먼저 읽을 것: `~/.agents/skills/hitl-eval-dashboard/SKILL.md` + references, brief 의 선행 프로젝트 교훈.
- 반드시 평가할 것(빠지면 제품이 망가지는 항목)과 그 근거. 반복 · 조건 변형에 대한 일관성이 정확도보다 먼저인지 판단.
- 판정 형식: 점수 척도 vs 씀 · 버림 + 실패 태그, 사람 판정 vs 자동 지표 vs LLM 판정. LLM 판정은 순서 뒤집기 재현성 근거와 함께.
- 기록 스키마: 입력 id · 설정 해시 · 출력 · 원가 · 지연 · 자동 점수 · 사람 판정 · 실패 태그 · 코멘트 · 재현 정보. 회차가 쌓여도 페이지를 새로 만들지 않는 구조.
- 테스트 데이터: 공개 데이터셋 라이선스, 내부 자원자 촬영 프로토콜, 합성 변형. 민감 데이터(얼굴)는 노트 · 클라우드 저장소 · PR 밖 로컬에만.
- 도구: 파일 기반(JSONL · SQLite) 우선, 외부 SaaS 는 사용자 결정 필요로 표시.
