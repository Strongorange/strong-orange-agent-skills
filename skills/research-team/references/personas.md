# 조사원 페르소나

## 도출 규칙

1. **판정 기준 하나당 그것을 가장 잘 따질 직업 하나.** 기준이 6개면 조사원 후보 6명에서 시작해 겹치는 것을 묶습니다.
2. **반대 근거 담당 1명 필수.** 지금 1순위 후보가 틀렸다는 근거, 다른 조사원이 놓칠 반례, 공급자 주장과 다른 실사용 보고를 찾는 사람. 가상 착용 모델 조사에서 조사원 한 명의 오류 4건을 메인이 종합 단계에서야 잡았습니다. 이 역할이 있으면 조사원 단계에서 걸립니다.
3. **평가 · 실측 설계 담당은 후보 비교와 분리.** 후보를 고르는 사람이 평가 방법까지 정하면 자기 후보에 유리한 기준을 씁니다.
4. 총원 10명 이하. 넘으면 비슷한 직업을 한 명이 질문 두 묶음으로 맡습니다.
5. 페르소나의 "배경"은 그 사람이 어떤 자료를 먼저 찾을지가 달라질 만큼만 구체적으로. 학위 · 경력 수식어로 길게 쓰지 않습니다.

## 4칸 템플릿 (한 명마다)

```
## P<n>. <직업> — "<이 사람이 답할 한 문장 질문>"

**배경**: 어떤 일을 해 봐서 어떤 자료를 먼저 보는 사람인지 1~2문장.

**먼저 읽을 것**: brief.md 외에 이 사람만 읽어야 하는 것. 파일 경로 · URL · 스킬(`~/.agents/skills/<x>/SKILL.md`) · context7 라이브러리 id. 없으면 "brief.md 만".

**질문** (3~6개, 번호)
1. …  ← lenses.md 에서 해당 렌즈의 체크 항목을 여기에 섞어 넣음
2. …

**산출 파일**: `<절대경로>/raw/P<n>-<담당>.md` — 반드시 들어갈 표 · 절 이름.
```

## 역할 예시 (주제에 따라 고르고 고침)

| 역할 | 주로 맡는 판정 기준 | 어울리는 렌즈 |
|---|---|---|
| 공식 문서 · 가격 · 라이선스 분석가 | 원가, 상업 이용, 지원 범위 | AI 모델, 벤더 API |
| 기반 기술 · 논문 연구자 | 품질 근거, 한계 · 잘 되는 조건 | AI 모델(3층), 방법론 |
| 대안 · 경쟁 후보 조사자 | "지금 후보가 아직 최선인가" | AI 모델, 라이브러리 |
| 반대 근거 · 실사용 보고 조사자 | 공급자 주장 반박, 실패 사례 | 전부 |
| 운영 엔지니어 | 실행 환경, 지연, 배치 가능성 | 라이브러리, 벤더 API |
| 평가 · 실험 기록 설계자 | 평가 방법, 기록 스키마, 데이터셋 라이선스 | 평가 설계 |
| 도메인 실무자 | 사람은 어떻게 판단하나, 어디서 갈리나 | 방법론 |
