# research-team

조사원 여러 명에게 **같은 공통 맥락**과 **각자의 페르소나 · 읽을 자료 · 질문**을 주고 병렬로 조사시킨 뒤, 메인(이 세션)이 결론을 바꿀 주장을 원문으로 다시 확인해 종합합니다. 가상 착용 모델 선정과 사진 기반 판정 방법, 두 조사에서 효과를 본 방식을 절차로 고정한 것입니다.

고정하는 것은 **절차 · 확인 수준 태그 · 산출 폴더**뿐입니다. 대상마다 달라지는 질문은 `references/lenses.md` 의 렌즈로 분리합니다. 입력은 자연어 주제 하나(+ 선택: 프로젝트 이름)입니다.

## 절차

### 1. 맥락 수집 (메인, 조사원 띄우기 전)

- 메모리 · 노트 저장소에서 관련 프로젝트 · 작업 기록을 읽어 **이미 아는 사실**과 **선행 프로젝트 교훈**을 모읍니다. 이게 없으면 조사원이 재조사만 합니다.
- 사용자에게 아직 없는 것만 묻습니다: 판정 기준의 우선순위, 쓸 수 있는 계정 · 자원, 금지 사항(유료 호출 · 기획 논의 등).
- 기획 논의를 먼저 꺼내지 않습니다. 에이전트는 10명 상한.

### 2. 공통 맥락 파일 작성

`references/brief-template.md` 의 칸을 전부 채워 `brief.md` 로 저장합니다. 칸 하나라도 비우면 그 칸에 대한 재조사 · 추정이 생깁니다. "이미 아는 사실" 절에는 **반박하려면 근거 필요**를 명시합니다.

### 3. 렌즈 선택 + 페르소나 초안 → 사용자 확인 1회

- `references/lenses.md` 에서 주제에 해당하는 렌즈를 고릅니다(복수 가능). 렌즈는 조사원 질문에 섞어 넣을 체크 항목입니다.
- `references/personas.md` 의 도출 규칙으로 조사원 초안을 만듭니다. 각 조사원은 배경 · 먼저 읽을 것 · 질문 · 산출 파일 4칸 필수. **반대 근거 담당 1명**을 꼭 넣습니다.
- 렌즈 · 조사원 목록 · 인원을 AskUserQuestion 한 번으로 확인받습니다. 확정본은 `personas.md` 로 저장합니다.

### 4. 조사원 실행

- Agent 도구, `subagent_type: general-purpose`, `model: sonnet`, `effort: medium` 기본. 전원 한 메시지에서 병렬 호출.
- 프롬프트는 "`brief.md` 와 `personas.md` 를 먼저 읽고 자기 절(P<n>)만 수행. 결과는 지정 파일 하나에만 쓰고 다른 파일 · 노트 · 브랜치는 건드리지 않음". 파일 경로는 절대경로로.
- 브라우저가 필요하면 `agent-browser`(세션 이름은 조사원 이름). 라이브러리 문서는 context7 우선.
- 조사원 보고 형식: 결론 1~2줄 → 후보 표 → 제외 목록(이유 한 줄) → 미확인 목록 → 출처 URL. 한국어 합니다체.

### 5. 종합 (메인)

`references/synthesis.md` 절차대로. 핵심은 **결론을 바꿀 주장을 원문으로 다시 열어 대조**하고, 바로잡은 것 · 조사원 간 모순 · 미확인을 각각 절로 남기는 것입니다. 보강 조사원은 모순이 원문으로 안 풀릴 때만 띄웁니다.

### 6. 보고

사용자에게는 결론 → 후보 표 → 뺀 것 → 바로잡은 것 → 미확인 · 다음 단계 순서로, 수치 · URL 은 표와 맨 끝 참고에만. 기획 제안은 넣지 않습니다.

### 7. 저장

- 프로젝트가 있으면 `<노트 저장소>/<프로젝트>/진행/<YYYY-MM-DD>-<주제>-조사/`, 없으면 `<노트 저장소>/work-logs/<YYYY-MM-DD>/<주제>-조사/`.
- 폴더 안 고정 파일: `brief.md` · `personas.md` · `raw/P<n>-<담당>.md`(조사원 원문 그대로) · `synthesis.md`.
- 정본 노트(work-log 또는 진행 노트)는 폴더 옆에 두고 결론 · 바로잡은 것 · 다음 단계만 담습니다. 조사원 원문은 복사하지 않고 링크.

## 예외 없는 규칙

- **주장마다 URL.** 공식 문서 · 모델 카드 · 가격표 · 라이선스 · 논문 원문이 1차, 블로그 · 커뮤니티는 보조.
- **확인 수준 태그 6종**을 표 칸마다 붙입니다: `[문서 확인]` 원문 직접 읽음 / `[2차]` 다른 문헌의 인용으로만 / `[주장]` 벤더 · 블로그 · 검색 요약 / `[논문→유추]` 기반 기술 · 논문의 한계에서 끌어낸 것(이 모델에서 재현되는지는 미확인) / `[실측 필요]` / `[추정]`. 태그 없는 칸은 종합에서 `[미확인]` 처리.
- **라이선스 · 상업 이용 가능 여부**는 모델 · 가중치 · 학습 데이터 · 라이브러리 전부에 적습니다. 기술 타당성 실측 단계에선 비상업도 후보에 두되 표시합니다.
- **날짜**: 공개일 · 최신 버전 · 실행 수 · 중단 예정일. "아직 최신인가"의 근거.
- **유료 호출 · 가입 · 파일 수정 · 커밋은 조사원 금지.** 실측은 메인이 별도 단계에서.
- **기획 · 가격 · UX 제안 금지.** 방법 · 근거 · 테스트 설계까지만.
- 조사원 총원 10명 이하. 넘으면 역할을 묶습니다.

## 참고

- `references/personas.md` — 조사원 도출 규칙 · 4칸 템플릿 · 예시
- `references/lenses.md` — 대상별 질문 렌즈(AI 모델 · 라이브러리 · 벤더 API · 방법론 · 평가 설계). 새 종류가 나오면 절 하나 추가
- `references/synthesis.md` — 메인의 교차 검증 · 종합 절차
